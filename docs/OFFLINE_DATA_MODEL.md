# 오프라인 문제와 풀이 세션

오프라인 학습은 과목, 문제, 풀이 세션 순서로 구성합니다. CSV 등록은 문제 원본만 만들고, 사용자가 풀이를 시작할 때 세션을 만듭니다. 같은 문제를 다시 풀어도 본문과 정답을 복제하지 않습니다.

## 변경 위치

| 파일 | 책임 |
| --- | --- |
| `src/types/test.ts` | 문제 원본, 세션, 화면용 세션, 백업 타입 |
| `src/lib/offlineProblemSets.ts` | 원본 문항 분리와 화면용 세션 조합 |
| `src/lib/dashboardBackup.ts` | 저장 데이터 검증, 구형 데이터 이전, 백업 통계 |
| `src/store/useTestStore.ts` | 문제와 세션 생성, 학습 기록 변경, 백업 snapshot 생성, 영구 저장 연결 |
| `src/lib/offlineDataStorage.ts` | IndexedDB 입출력, 직렬 저장, 탭 충돌 감지 |
| `src/hooks/useOfflineSession.ts` | 현재 세션과 원본만 읽어 공통 풀이 화면에 연결 |
| `src/lib/cloudBackupRestore.ts` | 복호화된 백업 검증과 서버 메타데이터 대조 |
| `src/pages/OfflineProblemSetSessionsPage.tsx` | 문제별 세션 목록과 생성, 이름 변경, 삭제 |

서버의 온라인 문제와 오프라인 원본을 같은 store에 넣지 않습니다. 온라인은 서버 API, 오프라인은 브라우저의 원본과 학습 기록을 각각 화면용 `TestSession`으로 변환해 CBT와 결과 화면을 공유합니다.

## 저장 구조 v4

DB `law-solver-offline`, object store `persisted-state`, key `law-solver-storage`는 유지합니다. Zustand persist 버전과 JSON 백업 버전은 4입니다. 환경설정과 미니 앱의 저장 구조는 바뀌지 않습니다.

| 엔터티 | 보관하는 값 |
| --- | --- |
| `Subject` | 과목 이름, 표지 팔레트, 표시 순서 |
| `OfflineProblemSet` | ID, 제목, 문제 유형, `subject_id`, 등록 시각, 수정 시각, 원본 문항 배열 |
| `OfflineQuestion` | 문항 ID, 번호, 본문, 지문, 선택지, 정답, 해설, CSV 원본 행 |
| `OfflineSession` | 문제 ID, 제목, 풀이 순서, 문항 ID 배열, 문항별 응답, 진행 상태, 점수, 시간, 회차와 재풀이 출처 |
| `OfflineSessionResponse` | 답안 `answer`, 오답 노트 `wrong_note`, 책갈피 `bookmark` |

`problemSets[].questions`만 문항 본문을 보관합니다. `sessions[].question_order`는 해당 문제 안의 문항 ID를 순서대로 가리키고, `responses`는 그 세션에 포함된 문항별 기록을 보관합니다. `sessionSubjectMap`은 더 이상 저장하지 않습니다. 과목은 문제의 `subject_id`로 결정하며, `null`은 과목 없음입니다. `NO_SUBJECT_ID`는 URL과 UI에서만 사용합니다.

`TestSession`과 `ParsedQuestion`은 기존 CBT, 채점 결과, CSV 내보내기에 필요한 화면 계약입니다. `materializeOfflineSession`이 원본과 응답을 합쳐 만듭니다. 이 결과를 다시 영구 저장하거나 전체 세션을 매번 조합하지 마세요. CSV 원본 행에는 가져온 파일의 값이 남을 수 있지만 현재 답안, 노트, 책갈피의 원본은 항상 해당 세션의 `responses`입니다.

## 생성과 변경

- `createProblemSet`은 문제 원본만 추가합니다. 등록 직후 세션 목록은 비어 있습니다.
- `createProblemSets`는 여러 원본을 입력 순서대로 생성하고 전체 검증 후 한 번의 상태 변경으로 반영합니다. 하나라도 잘못된 입력이면 기존 상태를 유지하며 빈 입력은 아무것도 변경하지 않습니다. 단일 등록도 같은 경로를 사용합니다. 저장 형식은 바뀌지 않습니다.
- `createSession`은 문제 ID와 풀이 순서를 받아 새 답안 공간을 만듭니다. 원본 문항 배열을 복제하지 않습니다.
- 전체, 오답, 책갈피 재풀이는 `sourceSessionId`와 `retryMode`를 전달합니다. 원본 세션의 문항 범위에서 새 ID 배열을 만들고 답안, 노트, 책갈피는 비웁니다. 오답에는 미응답도 포함합니다.
- 문제의 제목과 과목을 바꿔도 기존 세션 제목과 기록은 유지합니다. 문제 내용 교체는 지원하지 않습니다. 문항을 수정하는 기능을 추가하려면 이미 제출한 결과의 정답과 문항 참조를 보존하는 별도 정책부터 정하세요.
- 과목을 삭제하면 소속 문제는 과목 없음으로 이동합니다. 문제와 세션은 남습니다.
- 문제를 삭제하면 그 문제의 모든 세션도 삭제합니다. UI에서 범위를 안내하고 확인을 받습니다.
- 세션 삭제는 해당 세션만 제거합니다. 문제 원본과 다른 세션은 유지하며, 삭제한 세션을 가리키던 재풀이 출처는 해제합니다.

문제의 `created_at`은 등록 시각, `updated_at`은 문제 정보 수정 시각입니다. 세션의 `created_at`은 생성 시각, `last_played_at`은 실제 풀이의 마지막 활동 시각, `submitted_at`은 제출 시각입니다. 생성만 한 세션의 마지막 풀이 시각은 `null`입니다. 목록을 보기만 하거나 세션 이름을 바꿨다고 풀이 시각을 갱신하지 마세요. 전체 `dataUpdatedAt`은 백업 비교용 최종 변경 시각이며 이 시각들과 목적이 다릅니다.

## 기존 데이터 이전

구형 `TestSession[]` 배열, v1부터 v3까지의 백업과 저장 데이터를 검사한 뒤 v4로 변환합니다. 세션 하나마다 문제 하나와 세션 하나를 만듭니다. 제목이나 본문이 같아도 서로 합치지 않습니다.

1. 기존 세션 ID를 유지합니다. 생성하는 문제의 ID에도 같은 값을 사용하되 두 엔터티의 ID 공간은 별개입니다. 기존 `/solve/:sessionId`, `/result/:sessionId` 링크는 유지됩니다.
2. 세션 제목, 유형, 문항 본문과 정답을 문제 원본으로 옮깁니다. 세션의 기존 문항 순서는 그대로 `question_order`에 담습니다.
3. 답안, 오답 노트, 책갈피는 해당 세션의 응답으로 옮깁니다. 풀이 상태, 시간과 결과를 보존합니다.
4. 유효한 기존 과목 매핑을 문제의 `subject_id`로 옮깁니다. 과목이 없거나 사라진 매핑은 과목 없음으로 처리합니다.
5. 문제 등록 시각은 기존 세션 생성 시각을 사용합니다. 예전 형식에 없던 마지막 풀이와 제출 시각은 추정하지 않고 `null`로 둡니다. 화면에는 마지막 풀이 기록이 없음을 표시합니다.

v4를 다시 읽을 때 새 문제나 세션을 추가하지 않습니다. 알 수 없는 미래 버전, 중복 ID, 존재하지 않는 문항 참조 등 손상된 데이터는 복구를 중단합니다. 구형 데이터 정규화와 v4 검증 정책을 수정할 때는 `dashboardBackup.test.ts`와 저장소 회귀 테스트를 함께 확인하세요.

## 백업과 복구

새 파일 백업의 형태는 다음과 같습니다.

```json
{
  "app": "law-solver",
  "version": 4,
  "exported_at": "2026-09-20T00:00:00.000Z",
  "data_modified_at": "2026-09-20T00:00:00.000Z",
  "problemSets": [],
  "sessions": [],
  "subjects": []
}
```

IndexedDB hydration, JSON 파일 복구, 클라우드 복구는 같은 검증과 이전 로직을 사용합니다. 레거시 localStorage 원본은 초기 복사본 재확인과 검증된 변환 결과의 IndexedDB 영구 저장이 끝난 뒤 제거합니다. 저장 실패 시 원본을 남깁니다. 탭 충돌과 오래된 snapshot의 덮어쓰기 방지도 유지합니다.

클라우드 백업은 기존 gzip과 비밀번호 기반 암호화를 그대로 사용합니다. 서버는 JSON 내용을 읽지 않으며, 암호화 컨테이너 버전과 내부 백업 버전은 별개입니다. v4를 위해 서버 API나 DB 구조를 변경하지 않습니다.

클라우드 복구는 복호화 후 구조를 검사하고 필요한 경우 이전합니다. 이어서 서버의 과목 수, 세션 수, 원본 문항 수와 수정 시각을 대조합니다. 모든 검사가 끝난 뒤 사용자에게 최종 교체 확인을 표시합니다. 확인 후에도 IndexedDB 저장 성공 전에는 현재 메모리 데이터를 바꾸지 않습니다. 구형 백업은 세션별로 문제를 하나씩 만들기 때문에 이전 전후 문항 수가 같습니다. v4의 문항 수는 세션별 중복이 없는 문제 원본의 합입니다.

v4 데이터를 v3만 이해하는 구형 앱으로 되돌리는 하향 이전은 제공하지 않습니다. 배포를 되돌릴 때는 v4를 이해하는 수정 버전을 사용하고, 구형 앱으로 데이터를 읽거나 다시 저장하지 마세요. 작업 전 원본 JSON 백업을 별도로 보관하는 것이 복구 검증에 유용합니다.

## 화면과 확인 항목

`/dashboard`는 과목 책장, `/dashboard/:subjectId`는 문제 카드, `/dashboard/:subjectId/problem-sets/:problemSetId`는 세션 목록입니다. 세션 목록은 온라인과 공통 `SessionListItem`을 사용합니다. 이동한 문제의 이전 URL은 현재 과목 URL로 교정합니다. 동적 ID가 있는 경로는 검색 색인과 GA4 식별자 전송 대상이 아닙니다.

문제 등록 시각은 카드 하단의 날짜 태그에 표시합니다. 세션 날짜 태그는 마지막 풀이 시각을 우선 표시하고, 해당 기록이 없으면 생성 시각을 표시합니다. 툴팁에는 두 시각의 기록 여부를 함께 안내합니다. 세션 이름 변경과 삭제는 오른쪽 관리 메뉴에서 실행하며 문제 원본과 다른 세션에 영향을 주지 않습니다. 구체적인 높이와 정렬 기준은 [디자인 시스템](DESIGN_SYSTEM.md)을 따릅니다.

자동 검증에는 다음 경우를 포함합니다.

- 같은 제목의 구형 세션 두 개가 서로 다른 문제 두 개로 이전됨
- 진행 중 답안, 완료 결과, 오답 노트, 책갈피, 순서와 생성 시각 유지
- 한 문제에서 여러 세션을 만들어도 원본 문항은 하나이고 응답은 독립적임
- 오답과 책갈피 재풀이가 같은 원본을 참조하고 기존 결과를 보존함
- 구형 암호화 백업 복호화와 이전, 잘못된 메타데이터 거부
- 손상된 참조와 미래 버전 거부, 저장 실패 시 기존 데이터와 레거시 원본 보존
- CSV 등록 직후 세션 없음, 명시적 시작 후 생성, 문제 이동과 삭제 범위

전체 검증은 `npm run verify`로 실행합니다. 브라우저에서는 등록, 새 풀이, 중단 후 이어 풀기, 제출, 재풀이, JSON 복구를 순서대로 확인하고 모바일과 다크 모드에서도 목록 CTA와 긴 제목을 확인하세요.
